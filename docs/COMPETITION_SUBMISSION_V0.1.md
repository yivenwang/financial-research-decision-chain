## 项目计划书正文

### 项目与用户问题

Beacon｜研灯面向基本面研究中的持续更新任务。当新财报出现，研究者需要知道新增事实影响了哪些论点，原有假设是否需要复核，哪些计算可以复现，以及谁接受了这次修改。系统把来源、证据、论点、假设、计算、研究文案和版本记录连起来，帮助研究者在更新资料时保留判断依据。

首个案例为安克创新利润质量研究；当前自动传播限于 C-04 路径。用户可以输入一个研究问题，经模型识别任务并确认范围，再使用已登记、审核的财报证据形成结构化回答。材料上传与人工核查仍是必要的证据入口。

### 技术方案及人机分工

系统采用 Next.js 应用、保留坐标的 PDF 解析、固定规则计算、受约束的大模型输出和追加式审核记录。任务合同限定公司、期间、意图、指标和可用工具，服务端校验合同与证据快照；模型负责规划和解释，程序负责财务数值与规则，人保留研究假设及最终判断。

回答包含事实、同比及利润桥、引用、支持与反证、待补材料和影响说明，可导出 Markdown / JSON。用户接受内容与保存版本分别记录；人工修改 Memo 另建修订记录，原模型稿保留，回滚追加恢复版本。当前审核者为自行署名，数据保存在本机浏览器，不具备机构级身份鉴证或多人共享。

### 已有成果与评测方法

目前已实现真实 PDF 上传、三项候选指标、固定 C-04 传播、模型 Memo、人工改稿/审核、版本/导出/回滚及三意图问题入口。#24 / #25 已合并并通过普通 CI。历史 run-10 的三份 Memo 建议正文已由项目所有者确认；这不是新问题 Prompt 的真实验收或专业审定。

新问题验收采用预先固定的三题和相同 S-05 快照，每题最多两次模型请求，首个失败停止整批并保留输出。分别检查技术可重放性、问题相关性、引用准确性、原因推断边界和反证完整性。普通测试使用明确标识的合成模型传输，不充当模型质量数据；三个不同意图也不能替代多次复跑的稳定性证据。真实批次当前尚待执行与内容审阅。

### 价值与创新范围

项目的实现重点是把一次研究更新变成可查证、可修改、可追溯的记录：原材料和数值计算有出处，模型解释与计算分开，人类接受指向具体版本，失败也保留。我们不将多角色命名、漂亮报告或单次高分当作可信性的替代。

跨公司可复用性尚待新增公开报告验证，不能声称适用于任意公司。真正的任意快照字段差分、团队协作和持续跟踪属于后续工作；当前 Graph Diff 仅表示已有冻结路径与传播解释。不能据此宣称已经实现自动科学家、自动投资或普适商业效果。

### 风险与实施安排

主要限制为 PDF 格式覆盖、模型输出失败或无依据归因、单案例范围和缺少专业判断资料。相应做法是严格来源/期间/单位校验、事实程序化、模型失败阻断、完整留档以及专业待审标记。EG-01 / EG-02 保持 pending；年化展示占位不作为预测或可发布估值。

UI 定稿后按五页桌面工作台与 Mobile Companion 接入真实状态；随后在选定平台核对时限、来源校验与回滚，录制同一代码版本的演示。有限迁移验证、专家具体问题反馈和提交材料可以并行准备，任何新金融语义先说明影响再变更。
