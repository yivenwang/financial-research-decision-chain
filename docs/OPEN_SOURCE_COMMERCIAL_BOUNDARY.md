# Beacon｜研灯：开源与商业化边界 V0.1

日期：2026-09-23。状态：随本 PR 审阅的开发与发布边界；商业功能及私有仓库尚未创建。目标：短期交付可复现的比赛项目，长期保留产品化空间。

## 当前许可与发布原则

本公共仓库继续使用 Apache-2.0。已发布代码、提示词、文档与历史不会因本边界文档被追溯改为专有内容；第三方权利和单独许可仍按各自条款处理。本文件不修改 LICENSE，不禁止第三方对开源部分进行商业使用，也不承诺所有未来功能均开源。

Apache-2.0 授予遵守条款的接收者永久、不可撤销的版权许可，并包含第 3 条限定范围的专利许可。删除公开版本、改为私有或以后换许可证不能撤回已经授予的许可。未来独立模块可采用不同许可，但必须先确认作者及贡献者权利；不能假设未来所有贡献均由项目所有者独占。

## 模块边界

| 公共社区核心：继续维护 | 未来商业层：默认私有开发 |
| --- | --- |
| 已公开的研究链结构、证据血缘、确定性计算和人工审查规则 | 客户工作区、机构身份接入、权限、账单、运营监控与部署配置 |
| 参考 UI、公开接口、通用模型薄适配器 | 客户专用连接器、生产数据接入和合同约定的集成 |
| 合成样例、获准公开的样例与可复现回归 | 客户材料、授权研报、反馈记录、专有标注与未公开留出集 |
| 比赛运行说明、真实限制及失败历史 | 新增的专有校准、评测与评分策略、客户工作流及生产优化 |

同类文件不能仅凭名称判断归属：已经公开的提示词和规则继续开源；未来新增商业策略在公开提交前按权利与用途分类。公共代码中的现有功能不会因本表被搬走或删除。

公开仓库不能保存私有模块，即使放在名为 `private/` 的目录或未合并分支。私有实现只依赖公开、版本化的接口；公共 CI、演示与回归须能独立运行，不能依赖私有仓库权限或真实客户数据。商业层不得绕过冻结财务引擎、证据约束及人工专业关卡。

初期可在一个独立私有产品仓库中使用 `cloud/`、`enterprise/`、`data/` 模块目录，待权限或团队需求出现后再拆库，避免提前维护三个空仓库。创建仓库、迁移文件或修改当前仓库可见性均须实际操作后才可标记完成。

## 比赛与商业发布

- 比赛候选版本：在普通 CI、受控真实验收、内容复核和比赛要求核验后绑定准确提交。`competition-v0.1` 是拟用标签，尚未创建；当前技术测试不能代替内容和专业验收。
- 对外演示：公开核心与合成数据能够复现；模型调用、错误率、跨公司覆盖和专家批准只报告实际证据。
- 商业试点：先验证用户是否愿意为托管运行、数据接入、可审计协作、部署与支持付费，再开发对应私有模块。上述是商业假设，不是已上线能力或收入承诺。
- 每次公开提交：确认数据与代码的发布权、依赖许可证、模型服务条款；检查 diff 中不含客户材料、凭据和未公开评测答案。

## Jev 的本次位置

`adversarial-review.ts` 是公共核心中的可替换实验适配器，尚未接入正式问题路由。合成回放与本地测试不证明 Jev 的语义正确率，实验阈值没有金融场景校准。真实模型测试、正式调用预算、生产接入及客户数据处理仍需满足 [独立审查验收条件](ADVERSARIAL_REVIEW_V0.1.md)。

SDK 的开源许可证不等于托管模型服务条款。TypeSafe 当前条款限制使用服务或输出开发类似/竞争产品或做模型蒸馏；商业审查产品是否落入该范围，应在依赖其输出构建专有能力前向供应商确认。其不经事先同意用客户数据训练模型权重的承诺，也不等于零留存或禁止遥测。比赛实验使用获准公开或合成输入；客户输入、保留期限和 DPA 在商业试点前单独核实。
