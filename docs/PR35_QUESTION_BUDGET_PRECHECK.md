## 上限与估算

| 项目 | 控制 |
| --- | --- |
| 提供方请求 | 最多 6，三类固定问题各 plan/execute 一次；首失败全批停止、无自动重试 |
| 输入预算 | 每次估算 ≤16,000，全批预留 ≤96,000 |
| 输出 | 每次 max_output_tokens=6,000，全批 ≤36,000；包含 reasoning tokens |
| 保守费率 | 峰值、全部输入缓存未命中：输入 $1.32/M、输出 $3.96/M |
| 理论预算估算 | 96,000×1.32/M + 36,000×3.96/M = **$0.26928** |
| 25% 规划余量 | **$0.33660**；本地估算审批门槛 $0.35 |
| 金额硬上限 | **不具备**，上述金额不是实际账单保证 |

[官方价格](https://api-docs.deepseek.com/quick_start/pricing/?helper=penn&method=individual)
于本轮核查；不依赖缓存命中、谷价、赠送余额或促销。金额用整数微美元计算，不用
浮点金额累加。价格可能变化，未来执行前必须重新确认费率并审批最终新 SHA。
[Responses API](https://api-docs.deepseek.com/api/create-response/) 定义
max_output_tokens 包含可见和推理 Token，但未给每请求金额上限参数。

输入方法：计数**实际发往提供方的完整 JSON 正文** UTF-8 字节数，再加 4096 余量，
覆盖 system/user Prompt、证据、Schema、协议字段；在提供方 fetch **之前**检查。
这是偏保守的规划估算，未经提供方 tokenizer 证明，不能宣称精确输入 Token 硬限。
返回后核对真实 usage：缺失/非法、input 超预算或超估算、output 超 6000 等均停止，
不会启动下一请求。超过估算的已发请求可能已计费；超时/断连也不代表没有计费。
每个拟发请求先持久记录完整 16,000 输入预留；无 usage 的失败预留不退回。

现有实现不能实现真正金额硬上限：缺少已核验的提供方账户/Key 强制限额；实际
tokenization、价格变化、断连后的提供方处理以及共享 Key 的其他调用均不受本地
金额估算保证。没有读取真实 Key/余额、修改账户资金或创建付费设施。只实现请求
次数、输出参数、输入估算门禁和预算记录，不把本地 $0.35 门槛称为账单硬上限。
