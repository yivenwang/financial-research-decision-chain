# 系统方向与当前案例边界

更新：2026-09-08。依据项目所有者确认的主线，以及已合并 PR #14 的运行代码。

## 产品方向

面向二级市场投资研究者，帮助其在新材料出现后更新既有研究框架：核对来源与证据，定位受影响的论点和假设，执行确定性计算，生成带引用的备忘录，交由人判断，并保留历史。

系统围绕人明确设置的工作流运行，不以掌握研究者全部思维或替代最终判断为前提。长期目标是可复用的研究更新系统；安克创新承担首个验证案例的作用。

## 已实现与尚待验证

| --- | --- | --- |

| 证据与传播 | 必要证据逐条接受、拒绝或修改，冻结规则输出变化原因 | 只自动传播 C-04 及关联节点；其余五条论点明确保持不变。`apps/web/lib/research-engine.ts` 与 `lib/chain-v01.ts` |
| 变化说明 | 按 C-04 的已知关联列出受影响节点及规则解释 | 当前 `graphDiff` 不是任意研究图或两个快照的通用差分；列入 `changedNodeIds` 不证明每个节点值都相对前版改变。初始 V-01 也是预设基线，尚未验证任意旧研究框架的导入 |
| 假设与计算 | A-03、K-07、F-02 和估值输入接收本次变化 | 会计假设仍待专业复核；上传一次不产生连续可比期间序列。年化为展示占位，估值不可发布 |

| 人工判断 | 证据确认与备忘录接受/退回分别记录 | 系统信号与人工最终状态分开；当前切片保留原人工状态，尚未实现任意投资判断的编辑和专业审批流程。EG-01/EG-02 不由这些按钮关闭 |
| 版本追溯 | 研究快照和备忘录分别绑定，重载可读，回滚追加记录 | 当前保存在本机浏览器；不是多人同步库，署名未经身份验证，哈希不是数字签名。`research-versions.ts`、`research-memo-storage.ts` |
| 界面 | 材料更新和版本历史接入真实流程 | 标题、部分标签和决策链基线示例仍绑定安克；视觉方向与项目名待共同确定。`apps/web/app/page.tsx` |

上述代码路径以 [main 合并提交 93b1ea0](https://github.com/yivenwang/financial-research-decision-chain/commit/93b1ea09ff96875d6c2cf2ca47f0e8425cad1974) 为核对基线。系统骨架可以继续扩展，但当前还不能通过换一个公司名就完成迁移。

## 对外表述

可以表述为：我们正在构建可追溯的金融研究更新系统，已用安克案例打通 C-04 的一条技术流程，验证了证据审核、计算传播、模型备忘录和版本回滚。研究内容仍需人工与专业复核，跨公司适用性尚待验证。

“任意公司、任意 PDF、完整自主投资决策、六条论点全部自动更新、专业结论已获认可”均超出现有验收范围。单次真实模型成功不能转换成准确率或通用能力指标。

## 从首个案例走向系统的后续验收

以下是后续阶段的验收方向，不表示已经执行或获准改动核心逻辑。

1. 先完成本轮真实备忘录的内容修订与复核，保留原始成功/失败输出和评审意见。
2. 再选一家额外公司的一个可比报告，事先登记来源、预期支持范围和停止条件，保存首次输出。对照哪些机制可复用、哪些仍需修改，避免把适配后的回归当作首次泛化成功。
3. 根据迁移中实际暴露的差异，提出材料配置、研究框架与界面分离的具体改动，再由项目所有者批准。改变论点、阈值、估值、人工边界或模型判断要求都需单独说明。
4. 以一条完整演示、一次有限迁移和一份保留缺陷的评测记录结束首个案例阶段，转入参赛材料与答辩整合。

S-07 继续保持本阶段不读取、不测试。UI 与命名按 [UI 验收安排](UI_ACCEPTANCE.md) 共同推进；本阶段没有新增公司、改版、改名、部署或公开仓库。
