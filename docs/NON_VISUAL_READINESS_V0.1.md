## 实际交付

- PR #22 与非视觉收尾 PR #23 已于 2026-09-14 依次合并，主分支构建及浏览器回归通过；本页继续作为 UI、演示和专业复核的交接入口。
- 三份真实输出共 18 段全部核对：16 段有正文/引用建议，2 段建议保留。每份建议保留原 runId、快照摘要、原稿/建议摘要和逐段理由。当前字符数均在原有 160 字符约定内，既有引用/结构校验通过。
- 离线工具复算 28 个原文件的长度与 SHA-256；从三份快照重新核对现有冻结引擎、模型 context、原始 JSON 映射、原审核、Markdown 和建议绑定。所有原字节保留，新增真实模型调用为零。
- 输出只读 `index.html`、三份逐段核对稿、完整回放数据、原始文件及核验记录。没有产品导入/接受按钮，也没有新增或伪造人类签署。
- 新工具的四项本地边界测试通过；GitHub 独立 CI 验证同一工具及桌面/窄屏合成内容布局，具体运行链接在 PR 中回填。已有应用运行代码、模型 Prompt、预算和冻结规则保持不变，沿用 PR #22 的 42 项应用验收证据。

`docs/demo/run-10-revision-proposals.json` 是助手整理的编辑建议，不是模型评测标准答案；`run-10-archive-manifest.json` 只记录既有归档路径、长度和摘要。真实原稿与截图不复制进仓库测试 fixture，而由本地工具读取已有归档。工具与 CI 不使用密钥、不发起模型请求，不读取或测试 S-07。

2026-09-16，项目所有者明确批准三份全部按建议通过。追加的 `run-10-owner-review.json` 将决定绑定到三份准确建议、原调用和研究快照；原建议 JSON、模型归档和历史审核事件保持原样，浏览器修订台账没有被伪造写入。

## 本轮发现的明确边界

| 问题 | 处理结果与下一步 |
| --- | --- |
| 页面有实时结果，也有固定案例 | 对应表已经逐项标注；本轮没有改默认入口或将固定页伪装成动态结果 |
| `graphDiff` 不是通用前后快照差分 | 说明现有真实含义；若下一版需要真正字段差分，先确认产品语义与范围 |
| 原稿中 CI 接受与实际内容待修订并存 | 原事件继续保留；所有者已确认三份建议版本，专业复核继续 pending |
| 三份样本均称 V-02，但各自快照不同 | 离线包逐样本保留，不合并进同一浏览器研究库 |
| 部署路由声明 120 秒，模型请求最多 150 秒 | 运行方案列为平台发布前条件；未擅自改调用预算或声称上线可用 |
| K-07 clear 与会计定性 unknown 同时存在 | 交给专业人员评估含义；本轮保留原规则和待复核提示 |

## UI 定稿后的交接边界

UI 交付至少包括关键页面布局、配色字体及加载/空/错误/待审状态。此时可按本包的真实字段接入视觉，复用已验收的材料、证据、备忘录和版本组件。名称、整体入口/信息层级与视觉方向由所有者共同确认；代码改版附实际截图和完整任务操作验收，再制作 README 产品截图和视频。

剩余真实工作包括：把已确认正文按真实演示流程录入并导出、UI 设计与实现、有限跨公司首次验证、实际平台部署与预演、专业反馈、正式参赛材料。V0.7 / S-10 的独立未支持问题继续保留，不因本包完成而关闭。

数据库、多人协作、任意报告/研究框架导入属于长期路线图。系统主线保持“新材料 → 证据 → 论点/假设 → 确定性计算 → 备忘录 → 人工判断 → 版本”，安克是首个案例。
