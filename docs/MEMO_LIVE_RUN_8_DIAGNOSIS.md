## 结论与失败位置

DeepSeek 完整返回了最终 JSON，应用以 HTTP 422 / `MEMO_VALIDATION_FAILED` 阻断，唯一校验码为 `COUNTER_REFERENCE_MISSING`。失败发生在模型完成后的逐段引用检查，未到备忘录接受、正文导出和本轮回滚验收。

具体位置为 `counter[2]`，即第三条反证。该段讨论非经常性损益的持续性未知、缺少连续可比期间和会计定性待复核；引用只有 `EV-S-05-C04-NR` 与 `K-07`。在本次冻结输入中，前者的 direction 是“支持”，后者为 null，没有 direction 为“反证”的引用。

`validateMemo` 原本就要求 **每条** counter 至少有一条反证方向引用。前两段已经引用归母下降，不能替第三段满足要求。指标数值为负也不等于系统证据方向为反证，方向继续取自冻结引擎。本次未改变这些业务含义或校验。

这不表示资料缺失和假设待复核没有研究价值；它们可以作为论证限制，但这份输出的第三段不满足现有 counter 栏目的逐条规则。不能为通过校验而随意补一个正文未使用的引用，也不能把该段当作已被专业否定的金融观点。
