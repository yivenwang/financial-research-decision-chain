# Beacon 独立审查层 V0.1

状态：**实验模块，尚未接入正式问题结果的 PASS/BLOCK Gate**。日期：2026-09-23。

## 本次实际实现

1. 对已通过冻结引擎核验的研究快照与解释草稿，再执行现有的结构、引用、反证检查；失败时不会发起审查请求。
2. 生成仅含审核过的结构化引用、四段解释及已知限制的审查状态。解释文字仍是不可信的模型输出；不附带原始 PDF、独立用户片段、来源 URL 字段或 API 密钥字段；保留快照及状态哈希。这是字段选择，不是自由文本脱敏器，解释或引用中仍可能含敏感文字，不可直接用于客户数据外发。
3. 独立审查返回 `PASS_CANDIDATE / REVIEW / BLOCK` 和理由，全部保留 `humanGate: pending`。`PASS_CANDIDATE` 只表示候选草稿通过这一层，不是研究结论获批。
4. 可选 Jev SDK 适配器一次请求同时问三项：引用是否支持论断、反证是否处理、总体状态。显式固定模型名；禁用 SDK 默认的两次自动重试；失败降为人工复核。记录请求模型、返回模型、概率、用量、版本、快照与判定哈希。
5. Promptfoo 离线配置回放四个合成判定边界，不使用模型服务；`npm run eval:review`。它验证判定策略，不证明 Jev 的语义准确率。

## 为什么暂不改变正式产品 Gate

当前真实问题入口每次规划与执行各有一个独立、明确确认的模型请求。直接插入 Jev 会增加一次付费调用，并改变已冻结的验收预算和运行语义。当前没有 TypeSafe 密钥、固定模型版本、人工标注的审查样本或与 DeepSeek 基线的对照结果，因此不能把概率阈值视为校准过的金融风险关卡，也不能把 Jev 结果用于自动提交。

现有 `counterEvidence` 是已经运行的引用约束。本模块增加独立语义审查能力，但还没有完成主动检索新反证的 Falsification Pass。不得在答辩中把离线回放描述成真实 Jev 或多公司验证。

## 接入正式链路前的验收条件

- 冻结至少 20 个经人标注的研究状态，包含支持、冲突、证据不足及注入样例；保持训练/阈值选择与留出评测分离。
- 在同一快照上比较确定性规则、人工审查、DeepSeek Judge 和固定 Jev 版本；报告反证漏检率、错误放行率、人工分歧、延迟、用量与费用。需要显示置信区间或逐例分歧，不能用一张打勾表代替测量。
- 记录每次审查的完整版本、问题选项顺序和人类处理；原始失败只追加，不覆盖。
- 评估原始材料的提示注入和结构化输入污染；审查失败、超时或低置信度进入人工复核。
- 如需将 Jev 加进用户每次执行的正式流程，先修改调用预算、状态契约及 UI，再做真实端到端验收。保留原来的财务公式、专业关卡与人工最终判断。

## 本地复现

在 `apps/web`：

```bash
npm ci
npm run test:question
npm run eval:review
```

离线测试中使用的 `synthetic-key` 与模拟响应不会访问 TypeSafe。`jevJudge` 仅供显式控制的后续实验，必须由服务端提供密钥和固定模型名；当前产品路由没有调用它。

## 发布与商业边界

通用适配器与合成回放随社区核心发布；未来客户数据、专有标注和校准按 [开源与商业化边界](OPEN_SOURCE_COMMERCIAL_BOUNDARY.md) 管理。本模块不提供数据脱敏或零留存保证。
