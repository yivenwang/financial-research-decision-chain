# UI 共同优化与验收

## 已确认的用户要求

2026-09-05：后续在 GitHub 操作修改；对 UI 有要求；在合适的时间一起优化 UI。用户强调参赛目标，安克系统是验证案例。

目前未找回用户明确指定的配色、字体或视觉参考。因此以下“现有基线”和“建议验收标准”不应描述为用户已经选定的设计方案。

## 现有基线

保留 V5 的深色研究工作台、青色强调、卡片结构和五个页签。迁移阶段不重构 UI 主结构，不改财务业务规则。原始页面和样式可由迁移清单回溯。

## 何时一起优化

| 时点 | 一起看什么 | 完成标准 |
| --- | --- | --- |
| 网页在 GitHub 构建通过后 | 当前完整界面截图或可运行预览，以及用户喜欢的参考 | 记录用户反馈；选定视觉和信息层级方向，不在本次迁移里擅自换风格 |
| 第一条完整研究更新链集成后、视频录制前 | 上传/材料更新、证据与变化、决策备忘录、版本回滚 | 按真实任务路径完成一轮 UI 修改与操作验收 |
| 参赛演示冻结前 | 演示分辨率、加载/错误/阻断状态、回滚 | 屏幕录制清楚，用户知道每一步下一步做什么 |

视觉方向确认可以在模型接入期间进行，不必等所有技术问题解决后才开始。大规模布局修改应以完整任务实际使用的字段和步骤为依据。

## 建议验收标准（待用户一起评审）

- 第一屏能看懂项目当前在处理什么材料、什么发生变化、下一步做什么。
- 事实、机器推断、人工判断和历史结果各有清楚的文本状态，避免仅靠颜色区分。
- 证据可以定位到来源与页码，支持与反证同时可见。
- 阻断明确说明原因与解除条件；演示不得把禁止动作画成可用。
- 修改前后对比、专业待复核项、版本保存与回滚在任务中可找到。
- 表格数值、单位、正负号和同比易读；桌面录制和窄屏浏览都不遮挡关键操作。
- 键盘焦点、按钮名称、文字放大和对比度纳入最终验证。
- 每次 UI PR 附实际截图/短演示、完成的操作检查与遗留问题。
