## 案例收尾条件

一条完整可演示链 + 一次有限迁移验证 + 一份保留失败与不确定性的评测记录。达到后将主要精力转到材料与答辩；不把版本号、报表数量或 Star 数作为项目总进度。

## 协作方式

开发者在分支修改并提交 PR，说明问题、行为变化和验证范围。UI 由用户一起评审；财务业务定义和专业关卡有独立复核记录。正式合并、发布与公开状态分别记录，不将源码备份当作应用上线。

仓库目前为 private，准备公开展示后可记录自然获得的 Star、Issue、外部 PR 与真实使用反馈。Star 只说明关注度，不能替代评测准确率、采用情况或原创贡献说明。

## 当前约束

保留首次盲测、历史版本和回滚记录。S-07 的原始材料、真值和输出继续不读取，不在本轮运行；如果后续某个全量测试会触及它，先明确任务授权范围，不能根据旧文档中的 PASS 记录推断许可。
