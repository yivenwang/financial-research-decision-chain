## 演示主题

展示一份新财报如何进入已有研究框架，哪些证据和计算发生变化，哪些判断仍需人确认，以及这次工作如何被保存、复查和回滚。

项目使用描述名“可追溯金融研究更新系统”，不是最终品牌确认。安克是演示案例，C-04 是当前自动传播的一条论点。

## 录制前准备

- 使用 GitHub 仓库的已核验版本启动应用；保留本次代码 SHA。选择独立演示浏览器环境，保留已有研究历史。
- 备好 [官方 S-05 PDF](https://static.cninfo.com.cn/finalpage/2026-04-30/1225260221.PDF)。选择研究版本库；S-06 只用于独立回归演示，S-07 不进入本轮。
- 预先核对数字、页码和 F-02；核对清单见 [内容审阅记录](MEMO_CONTENT_REVIEW_2026-09-08.md)。日期、版本号以录制时真实记录为准，V-02 仅是空白演示库中的常见编号。
- 确认模型环境已配置，API Key 只留在服务器；演示访问码输入不进入公开录制画面。一次生成对应一次真实请求，记录等待时间与结果。
- 分清屏幕上的“决策链”基线示例与本次导入结果：现场证据以“材料更新”和“版本历史”为准。
- Graph Diff 当前展示 C-04 关联节点和冻结规则解释，不能声称已对任意两个研究图逐字段求差；系统信号更新也不等于所有关联节点的值都发生变化。
- 先完成用户确认的 UI 方向和任务可读性检查，再录制最终版本；项目名也需确认。当前脚本不要求立即改界面。

## 原始运行回放与现场生成

[第 10 次三样本归档](https://github.com/yivenwang/financial-research-decision-chain/actions/runs/34342481369/artifacts/10100481118) 可作为当前紧凑版备用回放素材，同时展示 [三份初审结论](MEMO_CONTENT_REVIEW_RUN_10.md)。第 5 次原归档保留为旧版历史。画面标明“历史技术验收回放”、运行编号、样本编号及内容修订项；引用其中一份做操作讲解时仍说明整批三份结果。CI 中的接受动作仅是自动化交互验证，不能称为用户或专业人员已接受内容。

新录制从产品真实入口生成并逐段审核；实际调用须另行安排，本次功能开发不启动付费生成。发现问题可退回，或按已审核证据建立人工修订稿、说明修改理由并另行审核。若原文不需要修改，直接按实际结论处理，不为演示制造问题。录制时重点展示一处真实修改，其余内容在录制前完整核对；不能用功能测试中的 CI 署名代替真实审阅。

若真实调用失败，展示其失败状态和阻断原因，再切换到有标注的历史回放。剪掉或加速等待时间时保留“已快进”标识；原始连续录屏和调用记录同时保留。采用备用方案不能将旧归档说成现场新生成。
