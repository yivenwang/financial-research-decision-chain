# 网页研究引擎接入 V0.1

2026-09-05。基于已合并的网页迁移 PR #11。

## 本次接入

网页通过 `apps/web/lib/research-engine.ts` 直接调用根目录已冻结的 Parser V0.6 Strict 与 Chain V0.1；根目录引擎、业务规格、历史测试均保持原文件内容。适配器负责审核和保存边界，不复制或重新定义 C-04 的金融规则。

真实路径：PDF 上传 → PDF.js TextItem x/y/page → 公司和期间匹配 Source 记录 → 完整性/同比 Gate → 三项 C-04 候选事实逐条审核 → 冻结决策链 → 系统信号/假设/失效条件/估值待补项/变化原因 → 证据审核人自填确认 → 版本追加 → 重载和回滚。

浏览器保存 PDF SHA-256、原始与审核后指标、来源页码、人工方向标注、系统方向、系统信号、完整 Chain 结果和证据审核人。审核人是自填记录，未验证身份；其签署范围是证据确认，不是 EG-01/EG-02 或投资决策批准。

## 严格边界

- 完整主表行缺失、原始解析 blocker、缺少接受的必要证据、无效数字、来源错配、同比或 F-02 不闭合，均阻断 Graph Diff 和快照保存。
- 人工方向标注保留在审核记录中，不能替代冻结规则计算的证据方向和系统信号。
- 系统信号单独保存；不再将“增强”等信号写入人工最终状态字段。
- 一个上传报告不代表连续可比期间序列。当前不将 Q1 与 H1 或重复上传拼成 K-07 的连续期间条件。
- 不复用其他期间股数，不自动批准假设，不发布估值或正式建议。
- S-06 保留 `regression-only`。通过材料选择进入独立回归版本库；它不能写入正常研究版本库。首次盲测结果及评分不变。
- S-07 不在本轮输入、测试或读取范围。

## 版本兼容

原研究库 key 和旧快照结构继续可读。新字段均为兼容扩展；回滚通过深复制创建新快照，保留系统链结果及恢复来源。新增写入检查防止损坏的版本库被静默当作空库覆盖；编号冲突停止写入。

新域名下的 localStorage 不会自动继承旧 Site 的用户记录，跨域数据迁移仍需另行实现并验收。

## 验证

本地运行原三项 parser fixture 与六项集成测试。集成测试覆盖严格完整性 Gate、人工审核、原始值保留、方向标注隔离、来源匹配、回归库隔离、回滚和损坏历史保护。

GitHub `Web research integration` 在生产构建后使用 Chromium 通过真实页面上传官方 S-05 和 S-06 PDF，执行审核、Graph Diff、署名、保存、页面重载、两次回滚；还检查错配材料、拒绝和空数值的阻断。PDF 下载仅限 Source 记录中的这两份已使用材料。浏览器测试调用产品原入口，不注入解析输出或调用隐藏应用接口。

命令：

```bash
cd apps/web
npm ci
npm test
npm run build
npm run test:runtime
```

浏览器工具使用独立临时安装的 `playwright@1.62.1`，不改应用 lockfile。环境变量 `PLAYWRIGHT_PACKAGE_PATH` 指向该包目录，再运行 `npm run test:browser`。具体可复现步骤见 `.github/workflows/web.yml`。测试报告与截图以 Actions 的实际结果为准，未通过时不得宣称端到端验收完成。
