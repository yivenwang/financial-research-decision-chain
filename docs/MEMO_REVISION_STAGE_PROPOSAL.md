# 人工修订与版本留痕：下一阶段提案

日期：2026-09-09。**待所有者批准；这里只提交方案，未实现功能、合并或部署。** 依据是 [第 10 次全部三份输出的审阅](MEMO_CONTENT_REVIEW_RUN_10.md)。

## 要解决的问题

固定版本三份 AI 草稿均已完成技术流程，但存在必须由研究者核对的引用和措辞问题。目前产品只能对模型原文接受、退回及追加意见，修改建议留在 GitHub 文档中。研究者缺少将修订后的正文与原始调用一起保存、复查和导出的入口。

建议把下一阶段用于完成这一步，让比赛演示呈现“模型起草、研究者核对并修订、记录谁确认了哪一版”的实际工作。第 10 次原始内容验收结论继续保留；人工修订通过不会变成 AI 原稿通过。

## 改前、改后与影响

| 项目 | 当前行为 | 拟议行为及影响 |
| --- | --- | --- |
| 正文处理 | 仅查看 AI 原文并接受/退回 | 从原文建立人工修订草稿，编辑六段正文及引用；必须填写修订者与理由 |
| 原始证据 | 研究快照和模型调用分别留存 | 修订稿绑定原 runId、研究版本及快照摘要，所有改动追加保存；保留原文、原引用、调用诊断及原审核事件 |
| 内容审核 | 接受事件绑定模型 run | 人工修订稿另有审核事件，绑定准确修订版本及内容摘要；保存修订不会自动接受，改下一版后旧接受不会自动继承 |
| 导出 | 模型备忘录和调用/审核记录 | 明确区分 AI 原文与人工修订稿，列出修订内容、理由及对应审核；不把人工写作计入模型输出 |
| 研究判断 | 备忘录不改写冻结计算或人工论点状态 | 修订和内容确认仍只影响备忘录；A-03、K-07、公式、估值、动作及 EG-01 / EG-02 沿用原权责和状态 |
| UI | 现有备忘录面板 | 在该面板加入原文/修订查看、修改正文与引用、保存及审核入口；整体视觉和品牌仍等用户参考后共同决定 |

这是新增人工处理环节及其数据绑定规则，按 [协作约定](../AGENTS.md) 需要所有者先确认。无需变更模型判断 Prompt 或重新生成同一批草稿。

## 最小实现范围

1. 六段编辑：本阶段处理当前紧凑版的完整六段原稿，每段显示该版本可用引用及其摘录，手动选择；沿用当前格式与引用校验，不自动补引或代写。只有完整且通过原约定校验的模型原稿可建立修订；旧版保留现有查看/审核方式，不隐式迁移，失败或截断输出继续不可作为备忘录使用。
2. 独立追加台账：修订稿记录自己的编号、原调用与快照绑定、前一修订编号、作者、时间、理由、正文及摘要。修订审核另行追加，明确绑定修订内容。作者、审核者仍为自行填写、身份未核验；不新增真实认证承诺。
3. 保持历史可读：原模型台账和研究版本保持原样；新修订台账损坏时阻断新写入，不覆盖旧值。回滚到一个新的研究快照时，不把旧修订或接受状态自动用作新结论。
4. 明确展示和导出来源：原稿保留原 Prompt / model / responseId；人工修订稿单独标记作者与修改理由。保存后默认待复核，接受或退回都是新的事件；后续修订重新待复核。
5. 演示脚本补入核对、修订、再确认步骤。历史 CI 的自动接受只展示为技术交互证据；展示正式内容确认时必须依据实际签署记录。

## 验收与费用边界

| 验收点 | 必须看到的结果 |
| --- | --- |
| 正常修订 | 修改一段及引用后，能保存、刷新读取、审阅及导出；原 AI 正文和调用逐字保留 |
| 错误绑定/无效引用 | 指向其他快照、未知引用或不合约定的内容不能保存或接受 |
| 连续修订 | 前版、理由及审核仍可查；新版本没有继承前版的接受状态 |
| 冻结状态 | 研究证据、确定性计算、人工论点状态、专业关卡、动作均与修订前一致 |
| 历史与回滚 | 旧版模型记录仍可读；回滚产生的新研究版本不冒用旧修订的审核 |
| 展示 | 原稿、人工修订、待复核及对应审核对象容易分辨，记录中的自行填写身份不冒充认证 |

普通回归用既有合成文案及明确标记的模型替身，检验上述持久化与绑定边界；不复制真实输出为测试标准答案。增加必要的浏览器流程检查并完成构建。审阅文档中的三份原文继续作为独立人工核对依据；任何正式修订展示保留来源和修订者，不改写原归档。

本阶段新增真实模型调用预算为 **零**，保持 DeepSeek 6,000 输出 token / 150 秒及已有 Prompt。只在当前 GitHub 开发分支准备实现和 PR，完成检查后交付审阅；合并、部署、公开、新材料接入、K-07 文案调整、整体 UI 和最终品牌分别确认。

## 与比赛主线的关系

交付目标是一条可复现的研究更新任务：材料与证据经过核对，计算有固定规则，AI 提供有引用的解释，研究者修订和确认，任何变化都能追溯。安克是首例，不能把这一功能完成声称为已跨公司通用。

功能通过后共同确认 UI、定时预演，并按既定边界提案验证第二家公司，同时完善计划书和视频。专业复核继续由实际专家承担。决赛 token 对照另行提出固定版本、次数、费用和时延方案，不与此功能验收混在一起。
