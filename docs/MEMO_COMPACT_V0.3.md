## 行为与代价

保留摘要、支持依据、反证事实与关联限制、待验证的替代解释、下一步研究问题五个栏目，共六段：前四栏各一段，研究问题两段。每段最多 160 个 Unicode 字符，引用一至八个；不预写研究结论，也不扩充财务输入。减少单份展开深度，先验证可完成、可核验的研究草稿。

版本：`research-update-v3-compact-1`；输出约定 `research-memo-output.v2-compact`。有效指令共 1,247 字符（前版 2,227），SHA-256 为 `f49922a31be029e29838e1d3f87cc10a8e615dc0b718c3e18f651090589e725e`。字符减少不等于 token 按同比例减少，也不证明质量提高。

`research-memo-contract.ts` 集中维护栏目、位置、长度、引用上限、标签和版本，供指令、Schema、本地校验及展示使用。新的模型返回使用固定对象位置：

| 模型返回 | 存储及界面 |
| --- | --- |
| summary：段落对象 | summary，原样 |
| supporting / counter / alternatives：各一段落对象 | 各自的单元素数组 |
| questions：仅 first、second 两个段落对象 | questions 数组，顺序保持 |
| gates：eg01 / eg02 均为 pending | 原样 |

每个段落只含 `text` 与 `citations`，所有对象字段唯一且不允许附加字段。完整 JSON 先检查重复字段和固定位置，再进行无损映射；不补齐缺失段落、不改正文、不自动补引，原始模型返回仍保存在 audit.rawOutput。映射后沿用原有台账与导出格式，不迁移或覆盖历史数据。

Schema 用必填对象位置限定六段，以 string pattern 表达长度，并用引用 enum 限定可用编号；本地按 Unicode 字符数作硬检查（包括末尾换行），并检查非空正文、引用数、方向、来源覆盖和专业关卡。不引入未经确认的 minItems / maxItems / minLength / maxLength 等参数。DeepSeek 的 Responses 文档支持 json_schema；其工具严格模式文档列明部分长度和数组参数不支持，因此这里保守选择对象、pattern 和 enum，实际端点行为仍由本轮真实调用确认。[Responses API](https://api-docs.deepseek.com/zh-cn/api/create-response/)、[Schema 类型说明](https://api-docs.deepseek.com/zh-cn/guides/tool_calls)。

历史 Prompt 版本有明确列表，继续使用原有八百字符及一至三条的安全校验，不套用新草稿的篇幅限制。旧反证栏目标签仍为“反证与限制”；旧调用、原文、审核与未记录的诊断字段保持原样。未知版本不能被当作旧版本放行写入或审核。普通浏览器回归仍明确使用模拟模型返回。

## 原判断要求逐项核对

| 要求 | 新版保留方式 |
| --- | --- |
| AI 做研究权衡 | 权衡支持与反证、提出替代解释和具体补证问题，不只复述信号 |
| 数据不是指令 | context 中的文本一律是数据；不用外部知识充当已验证事实 |
| 选定输入不等于报告全文 | 缺失资料限定为本次输入未提供，不推断报告未披露 |
| 事实、规则、解释、假设分开 | 摘要同样遵守，系统信号仍为冻结规则输出 |
| 会计前提不能自动成立 | 推及核心经营、扣非代表性或排除调整项时，同段限定待复核并引用 A-03 |
| 比较不能证明原因或持续性 | 不从方向、增速差、正负及桥闭合推断原因、代表性或未来恢复 |
| 非经常性不等于未来不重复 | 不直接改称一次性项目，正负不证明经常性 |
| 原因与替代解释 | 有明确披露才转述；未知机制进入替代解释，标记假设，给出观察和所缺证据 |
| 高估、低估须有比较依据 | 无依据不作判断，不预断未来利润恢复 |
| 每段引用 | 覆盖本段事实、比较两侧、假设及规则限制，含摘要；不罗列未使用引用 |
| 方向与反证 | 支持、反证各段陈述并引用对应方向事实；中性规则和负数不能冒充反证 |
| 覆盖与期间 | 全部原始财务证据仍须覆盖；同比为较上年同期，未知期间不补造 |
| 定性正文 | 数字、来源留给程序事实表，引用编号只进 citations；禁数字、百分号、网址、HTML、目标价 |
| 冻结计算与人工权责 | 不改指标、公式、信号、假设状态、估值、动作或人工判断；不给买卖建议 |
| 专业复核与分歧 | EG-01 / EG-02 保持 pending，逐段保留条件和分歧，不用文末免责声明代替 |
| 年化 | 仅展示占位，不是盈利预测 |

以上是指令要求对照，不是机器已验证模型遵守这些语义。逐条引用存在仍不等于推论成立。

## 一次手动批次如何执行

本次已批准批次已作为 [第 10 次](MEMO_CONTENT_REVIEW_RUN_10.md)执行完毕；以下说明保留其运行方式，不授权再次启动。该批次在普通回归通过后，从 Actions 的 **Live DeepSeek research memo acceptance** → **Run workflow** 选择 **dev/memo-judgement-v02** 与 **deepseek-v4-pro**，固定提交 `0a41f24`，一次启动最多三个样本。检查结果见 [PR #16](https://github.com/yivenwang/financial-research-decision-chain/pull/16)。旧运行的 Re-run jobs 不会验证新提交。

工作流只允许手动触发；固定本次 GITHUB_SHA，每个样本独立走 S-05 真实 PDF 上传、审核、保存、单次模型请求、导出和回滚。顺序执行；每个浏览器样本在发送前阻止第二个模型 POST。任何样本接口、截断、结构、审计或流程失败都会停止剩余样本；没有自动重试或第四个样本。

每个样本仍为 DeepSeek V4 Pro / low / 6,000 输出 token / 150 秒，批次最多 18,000 输出 token，另计输入；普通 CI 不进行真实调用。各样本的输入 context 除独立快照摘要外，以及返回模型名称，必须一致；若不一致，批次停止并记录。Prompt 版本、哈希及实际请求上限逐份核对。

同一个 Actions artifact 包含 `live-batch-manifest.json` 与各自的 `sample-01/`、`sample-02/`、`sample-03/`。执行前先记录样本已启动；每份保留自己的调用、原文、状态、用量、时长及截图，不挑选最好的一份。中断时没有提供方用量的样本明确记为未知，不补记为零消耗。

三份均完成只标记 `technical-completed-awaiting-content-review`，内容复核仍 pending。浏览器自动点击“接受备忘录”仅检验交互，其自行填写身份未核验，也不批准专业关卡。必须分别检查支持、反证、归因、会计前提和研究问题，再决定本版本是否初步重复验收通过。三个案例内结果不是产品成功率、长期稳定性或跨公司能力证明。

## 决赛 token 额度

所有者提出为最终效果考虑提高额度，可以安排在决赛彩排前用固定版本、相同材料做有限对照，评估完整输出、内容复核和等待时间后固定配置。较大额度能够提供更多生成空间，但不能保证事实或推论正确；正文仍可以保持精简。

token 是文本计量单位，不等于英文单词。`max_output_tokens` 包含推理和可见正文，low 不是固定的推理配额。按 2026-09-09 查到的 DeepSeek Pro 高峰输出价 ¥27 / 百万 token，若实际用满，6,000 / 12,000 / 16,000 输出 token 分别约 ¥0.162 / ¥0.324 / ¥0.432，均另计输入。提高上限本身不代表必定用满；时延与质量需实测，价格临近比赛时重新核对。[官方计费](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

本次保持已批准的 6,000 / 150 秒。上述较高额度是后续比较候选，尚未设为运行配置，也未授权额外对照调用；届时将连同等待时间、调用次数和验收条件一起提出具体方案。
