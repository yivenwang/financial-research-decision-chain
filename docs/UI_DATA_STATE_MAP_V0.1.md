## 先读这张表

| 当前入口 | 用户任务 | 实际数据与组件 | 设计时须保留的含义 |
| --- | --- | --- | --- |
| 默认“材料更新” | 选择已登记材料，上传 PDF，核对三条候选证据 | `UpdateWorkflow` 的 `source`、`parserResult`、`candidates` | 当前只有 S-05 / S-06；S-06 独立回归。PDF 在本机解析，上传不等于证据已通过 |
| “材料更新”中的审核与结果 | 接受/拒绝或改审核数值，查看阻断及规则结果，填写审核人后保存 | `reviewAndRun` → `ReviewedRun.chain`、`formula`、`blockers` → `createResearchSnapshot` | 方向来自冻结规则；审核数值与原值同时保留。保存的签署范围为证据 |
| “版本历史” | 选择研究/回归库和一个已保存版本 | `VersionHistory` 的 `workspace`、`selectedVersion`；`ResearchVersion` | 页面主数据必须全部来自当前选中版本，不能混入另一个版本的数值 |
| 选中版本的模型备忘录 | 查 AI 原稿与引用，生成或审核、导出 | `MemoPanel`；`MemoRun.context/memo/audit`；独立 `MemoReview` | 仅结构化证据送给模型；生成、保存、接受是不同动作 |
| 原稿中的“人工修订与版本记录” | 改六段正文/引用，填理由，保存，另行接受或退回 | `MemoRevisionPanel`；`MemoRevision` 与独立 `MemoRevisionReview` | 新版始终重新待审；显示当前选中修订的状态，历史稿只读 |
| “版本历史”中的回滚 | 选择旧研究版本，确认后追加恢复版本 | `createRollbackSnapshot` → `appendVersion` | 新版本有新编号及父版本；旧研究、模型和修订记录均保留 |
| “决策链” | 理解固定案例结构 | `app/page.tsx` 中预设 `evidence`、`claims` 与演示数值 | 已标为基线示例；此页不是本次导入/回滚的实时结果。“复算”按钮含演示延迟，不是实际新 PDF 计算 |
| “数据契约”与“历史盲测报告” | 理解字段与开发验证历史 | 预设说明/历史记录 | 不把这些卡片当作本次研究结果或用户完成度；本轮不读取或测试 S-07 |

现有第一步是材料更新，但“已有研究任务 → 查看变化 → 需要时加入材料”可以作为下一版入口提案；本轮没有把这一提案视为已确认的产品改动。

## 页面最少需要绑定的字段

| 视觉模块 | 数据来源 | 必须同时展示或允许展开 |
| --- | --- | --- |
| 当前研究上下文 | `ResearchVersion.versionId/source/workspace/createdAt` | 公司/材料期间、原文、版本、研究或回归用途；全局硬编码安克标题与状态标签不能被当作动态字段 |
| 候选事实 | `CandidateEvidence`；保存后 `ResearchVersion.evidence[]` | 标签、单位、原值、审核值、比较值、披露同比、复算同比、原文片段/页码、审核状态 |
| 支持与反证 | 证据的 `systemDirection`、`direction` 及 `chain.evidence` | 明确哪项事实支持、哪项事实反向；不能只显示有利证据 |
| 论点结果 | `chain.claim` 与 `ResearchVersion.claim` | 规则信号、原人工状态、当前人工状态分开；当前切片保留人工“成立”，不能说 AI 已完成投资决策 |
| 影响说明 | `chain.graphDiff` | 已知路径和解释。`changedNodeIds` 表示本轮列入传播的节点，不证明每个节点相对旧版的值改变 |
| 会计假设/失效条件 | `chain.assumption.status`、`chain.killCriterion.currentState/accountingState/consecutiveNonPositivePeriods` | A-03 待专业复核；K-07 的规则状态与缺少连续期间/会计定性同时说明，不能将 `clear` 翻译为“风险已解除” |
| 确定性计算 | `ResearchVersion.formula` 与 `chain.formula` | 两个利润口径、非经常性损益、差额、单位、闭合状态；本期桥闭合不是跨期稳定性证明 |
| 估值与动作 | `chain.valuation`、`chain.decision`、`blockedGates` | 年化展示占位、缺失股数/倍数和待复核项；“继续研究”与正式建议区分 |
| AI 文案 | `MemoRun.memo`，引用取同一 `MemoRun.context.references` | 摘要、支持、反证、替代解释、两条研究问题；不能将另一份样本的引用补进本稿 |
| 人工文案 | 当前 `MemoRevision.memo`，差异取当前版与父修订 | 修订者、理由、时间、原稿入口、审核范围；自行署名且身份未核验 |
| 审核/导出 | 分别读取原稿审核与修订审核，按 runId/修订编号/摘要绑定 | 用户看到的版本应与导出所选版本一致；历史稿导出提示已有更新稿 |

开发者应优先使用导出对象和现有组件类型；上表说明业务含义，不引入新的数据库 schema。[离线数据包](DEMO_REPLAY_V0.1.md)保留全部三份真实样本及其引用，供字段核对。

## 状态及下一步动作

| 状态 | 页面要说明 | 可以继续做什么 |
| --- | --- | --- |
| 未上传 / 解析中 | 当前等待什么；解析时避免重复操作 | 选择材料并上传；等待解析结束 |
| 解析失败 / 来源不符 / 缺行 / 复算不符 | 具体阻断原因及对应材料/指标 | 核对来源、格式和数值；不能生成正常证据并保存 |
| 证据待审 | 还有哪些必需指标未处理 | 逐条核对；任一必需项未接受则不能推进 |
| 已审但不能推进 | 全部“处理过”不代表全部“接受” | 修正被拒绝、无效或不一致的项 |
| 可保存 | 展示本次规则结果及专业待复核项 | 填证据审核人并保存研究版本 |
| 模型未配置 / 访问码不足 | 服务尚不可生成，不显示虚构草稿 | 查看已有历史；由部署者配置服务 |
| 模型生成中 | 正在等待一次调用 | 等待完成；不自动重试或另起请求 |
| 模型失败 / 截断 / 校验阻断 | 失败记录与原因；没有可接受的完整草稿 | 核对记录后决定是否另行生成；保留失败历史 |
| AI 原稿待审 / 接受 / 退回 | 明确是原稿的内容状态 | 核对、审核、导出，或创建人工修订 |
| 人工编辑未保存 | 字符数、引用数、未保存提示 | 修改、取消或保存；切换/刷新前先保存，当前没有自动草稿恢复 |
| 修订待审 / 接受 / 退回 | 精确绑定这一版正文和引用 | 审核最新稿、导出；继续修订后重新待审 |
| 历史修订 | 原理由、当时状态、是否有新稿 | 查看/导出；新编辑和新审核以最新稿为基础 |
| 存储/绑定/并发失败 | 写入未完成及恢复办法 | 保留未保存内容，核对最新记录；不清空旧库“修复” |

## 给队员的 UI 交付要求

寻找素材时至少覆盖材料/证据表、影响与计算、备忘录修订、版本历史四类任务。可提供参考图和标注，不要求队员实现接口或代码。配色、字体、关键页面布局，以及加载/空/错误/待审状态一并确认；名称与整体视觉仍由所有者决定。

建议同屏或一次展开就能回答：我在看哪份研究？新材料提供了哪些不同方向的证据？哪些判断仍需人确认？我现在能做什么？保存后去哪找？

以下三件事先由所有者确认，开发不得借 UI 改版悄悄加入：是否更换任务入口；是否建立真正的前后版本字段差分；是否允许编辑投资判断或改变专业审批。数据库、多公司模板和多人同步属于后续路线图。

验收使用一个明确版本的 S-05 流程；保留 S-06 回归隔离。当前基线 V-01 为预设记录，不能将它画成已完成全文解析的年度报告。三份历史样本虽然都叫 V-02，快照摘要不同，必须独立处理。
