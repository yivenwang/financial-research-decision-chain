## 使用方法

1. 从“版本历史”选择已保存的研究版本，打开一份完整的当前六段 AI 备忘录。点击“创建人工修订稿”。AI 原稿、固定事实和原稿审核仍可展开查看。
2. 逐段修改正文；在“选择本段引用并核对摘录”中检查证据、比较两侧和假设限制。每段有字符数和引用计数。所选引用只来自这一研究版本，系统不代写、不补引。
3. 填写修订者与具体修改理由，点击“保存人工修订”。修订稿另存为新版本，状态为“修订稿待复核”；原 AI 稿已被接受也不会使修订稿自动通过。
4. 审核最新修订稿，填写审核人和意见，选择“接受此修订稿”或“退回此修订稿”。审核只确认这份备忘录内容，会计、估值关卡和研究动作仍沿用原状态。
5. 需要再改时点击“继续修订”。“本次改动”可查看正文及引用的前后差异。新保存稿再次待复核，前版及其接受/退回事件全部保留。历史稿可查看、导出，继续修订及新审核以最新稿为基础。
6. “导出人工修订稿”得到当前所选修订的 Markdown，附修改差异和 AI 原稿；“导出修订与原始记录”得到完整 JSON，包括所选修订编号、原始调用与原审核、各次人工修订及修订审核。历史版本的导出明确提示已有更新稿。

作者和审核者为自行填写，身份未核验。保存地点仍是当前浏览器；导出有助于研究者带走记录。本机哈希用于一致性校对与绑定，不是数字签名或专家认证。

## 给 UI 队员的任务说明

用户是正在更新既有公司研究的研究者。本环节解决的问题是：读完 AI 草稿后，怎样把核对过的修改保存下来，并说明谁确认了哪一版。当前案例为安克 / C-04；本说明描述已实现行为，整体产品定位和视觉取舍继续由所有者共同确认。

| 用户所处位置 | 输入与操作 | 输出和下一步 |
| --- | --- | --- |
| 版本历史中的 AI 原稿 | 打开已保存研究版本的一份完整六段草稿，核对固定事实和引用 | 按实际内容审核原稿，或创建人工修订稿 |
| 人工编辑区 | 改正文和引用，查看摘录，填写修订者及具体理由 | 保存为独立修订；格式、引用或绑定不合格时停留编辑区并提示 |
| 最新修订稿 | 查看正文及本次改动，填写审核人和意见 | 接受或退回当前这份内容；再次修改产生新的待审版本 |
| 修订历史 | 选择某份旧稿，核对其理由、差异和审核事件 | 只读查看或导出，继续编辑以最新稿为基础 |
| 导出与研究回滚 | 导出所选修订和原始记录；在研究版本历史中执行回滚 | 留下可复查记录；新研究快照不会继承旧备忘录的接受状态 |

必须让用户分清：AI 原稿的审核状态、人工修订稿的审核状态、当前未保存编辑、专业关卡状态。保存修订后是“待复核”；接受只适用于准确的一份修订内容。每次修改的理由和前后差异应容易找到。

现有能力包括本机浏览器持久化和导出；跨设备同步、账号认证、多人审批、任意投资判断编辑属于尚未实现的能力。未保存编辑仅保留在当前编辑会话中，刷新或切换研究版本前应保存。整体 UI 参考和品牌确认继续按 [UI 安排](UI_ACCEPTANCE.md)推进；功能验收截图用于 PR 审查，README 的产品展示截图仍等 UI 定稿后制作。

## 保存与绑定

人工修订保存在独立台账 `financial-research-memo-revisions-v1-<workspace>`，不改写模型台账或研究版本键。研究库与回归库分别保存。

| 记录 | 绑定与信息 |
| --- | --- |
| 人工修订 | 独立编号、原调用编号、研究版本与快照摘要、完整原始调用摘要、前一修订编号、正文与引用摘要、作者、理由、时间、human 来源、memo-only 范围 |
| 修订审核 | 独立编号、准确修订编号、内容摘要、原调用与快照摘要、接受/退回、审核人、意见及时间 |
| 修订导出 | 所选修订编号、原调用及原审核、该调用全部人工修订及审核；模型用量只归属原模型调用 |

写入前重新核对原研究版本、冻结引擎及 context；模型保存正文必须与原始最终 JSON 无损映射一致。所有修订保留当前格式、引用方向与来源覆盖校验，不能借人工编辑关闭专业关卡。

同源页面的修订写操作使用浏览器 Web Locks 串行处理，并在异步核验后再次检查读取记录未被更改。两页同时从旧稿保存时只允许一个成为新版本，另一页必须先核对最新稿。该功能需要支持 Web Locks 的浏览器及安全上下文（HTTPS 或 localhost）；不支持时明确阻断保存。

遇损坏台账、无效引用、原始调用/快照变化、过期修订或存储容量错误时停止相关写入，编辑区保留未保存内容。回滚产生新研究快照，旧修订及其接受状态不会自动成为新快照的结论。旧 Prompt 草稿继续按原有方式查看及审核，本阶段不把它们迁移成六段。
